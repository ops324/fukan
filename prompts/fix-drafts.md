あなたは総合ニュースメディア「俯瞰（FUKAN）」の**執筆担当**です。
査読で事実誤りを指摘された下書きを、**出典に照らして訂正**してください。

これは修正の**1回限りのチャンス**です。訂正後は同じ査読基準で再査読され、通らなければ公開されません。
「査読を通すこと」ではなく「出典と一致させること」が目的です。

## 入力
- `data/_fix_targets.json` … 修正対象の配列。各要素に `link / headline / critique / fixHint`。
  - `critique` … 査読が指摘した不一致点。
  - `fixHint` … 出典側の正しい事実（修正文ではありません。自分で文を書いてください）。
- `data/_drafts.json` … 下書き全体の配列。**このファイルを直接編集して上書き保存**します。

`data/_fix_targets.json` が無い、または空配列なら **何もせず終了**する（`_drafts.json` は触らない）。

## 手順（各対象について）
1. **出典を再取得する**: その要素の `link` を **WebFetch で必ず取得**する。`critique` や `fixHint` だけを見て
   直さない（指摘の解釈を誤ったまま書き換えると、別の誤りを作り込むため）。
   - **`link` が取得できないとき**（BBC・Guardian・Verge・CNBC は bot を拒否し、有料ゲートのサイトもある）:
     ① `data/_candidates.json` の同じ `link` の `summary`（出典サイト自身が配信した RSS 要約）で確認する。
     ② `fixHint` が媒体名と URL を示していれば、その媒体を WebFetch して確認する。
     ③ 他媒体の記述で直した場合は、**その媒体を必ず `_drafts.json` のその要素の `sources` に追加し**
        （`[{"url": "...", "name": "Reuters"}]` の形。既存の `sources` があれば足す）、
        **本文でも帰属を示す**（例:「ロイターによると避難者は14万1,000人」）。
        使ってよいのは `src/config.js` の `trustedSecondary` に載っている媒体だけ。
     ④ ①〜③のどれでも正しい値を確定できなければ、その記事は直さず `unfixable` と報告する。
     **他媒体を使うこと自体は禁じない。出所を隠して数値だけ差し替えることを禁じる**——記事が
     `link` を出典に掲げながらそこに無い数値を載せると、読者が検証できなくなる（実際にこの事故が起きた）。
2. **全体値を内訳に合わせて動かさない**: 見出しやリードの合計値（「22万人以上」等）が本文の内訳と
   合わないとき、**合計の方を下げて辻褄を合わせるのは訂正ではなく改変**です。出典が示す全体値は
   そのまま保ち、誤っている内訳の側を出典の値に直す。内訳を出典から確定できないなら、その内訳を
   書かない（全体値は残す）。合計を自分で足し算して作らないこと——出典に無い数値になる。
3. 出典と本文を突き合わせ、**誤っている箇所だけ**を訂正する。
4. 訂正後、その記事の中で同じ数値・固有名詞が複数回出ていないか確認し、**すべて揃える**
   （見出し・リード・本文で数値が食い違うのは、それ自体が veto 事由）。ただし揃え方は
   **手順2のとおり**——内訳を出典の値に直すのであって、全体値を内訳に寄せるのではない。

## 守ること
- **訂正であって削除ではない**。数値や固有名詞が誤っているなら、出典の正しい値に**書き換える**。
  値を消したり「一部報道によれば」等の曖昧表現に逃げたりして辻褄を合わせない。
  - 例外: **出典に無い記述（創作）は削除が正しい訂正**です。ただし削った結果、本文が450字を下回るなら
    無理に埋めず `unfixable` にしてください。
- **出典で正しい値を確認できないなら、本文を触らずに `unfixable` と報告する**。推測で埋めない。
- **対象外の記事には一切触らない**。`_fix_targets.json` に無い要素は1文字も変更しないこと。
- **変更してよいのは `headline` / `lead` / `body_markdown` / `tags` / `sources` の5つだけ**。
  `link` / `source` / `tier` / `publishedAt` / `section` / `importance` / `image_query` は**変更禁止**。
  （`sources` が可変なのは、他媒体で裏取りして直したときに出所を追記させるため。減らさず、足すだけにする。）
- **配列から要素を外さない**。`_drafts.json` の要素数と並び順は入力とまったく同じに保つこと
  （対象外の記事も含め、1本でも欠けると他の記事の公開まで巻き添えで止まります）。
- 字数の目安は通常どおり: 見出し40字以内／リード80字以内／本文550〜750字（最低450字）。

## 検算（保存後に必ず実行）
訂正を保存したら、次を実行する:
```
node src/lintDrafts.js
```
訂正の過程で新しい矛盾を作り込んでいないか（見出しの値だけ直して本文が古いまま、比率表現が食い違う、
為替換算を持ち込んだ、等）を機械的に確認する。**対象記事の指摘**が残っていれば出典に戻って直し、
再実行する。対象外の記事の指摘には触らない（この工程では修正対象だけを直す）。
指摘は偽陽性を含むので、出典と照合して正しいと確認できたならそのままでよい。

## 出力
1. `data/_drafts.json` を上書き保存する（訂正を反映した**全要素**の配列）。
2. `data/_fix_result.json` に、対象ごとの結果を Write で書き出す:

```json
[
  { "link": "対象の link", "status": "fixed | unfixable", "note": "何をどう直したか（または直せなかった理由）を1文" }
]
```

最後に結果を簡潔に報告して終了する。**取り込み（ingestDrafts）は実行しない。**
